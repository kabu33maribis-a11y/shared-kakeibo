# 同棲・共同生活向け 共有家計簿アプリ 仕様書

Next.js (React) と Firebase を用いて、2人で簡単かつリアルタイムに支出を共有・精算できる Web アプリ（PWA）の基本仕様です。  
Excel データ（5月分）の運用実績を反映し、デジタルならではの利便性を追加した設計です。

## 1. アプリ概要

### 1.1 コンセプト

**「手入力は最小限。2人の支出と精算が1秒でわかる家計簿アプリ」**

Excel での丁寧な管理（誰が何にいくら使ったか、品名・カテゴリの明記）の良さを残しつつ、スマホからの入力の手軽さと、毎月の「立替金・精算の計算」の完全自動化を実現します。

### 1.2 メインターゲット

同棲生活やルームシェアなど、1つの家計を2人で共同管理・精算しているユーザー（例: かい さん、みゆう さん）

## 2. 機能要件（MVP）

### 2.1 ユーザー管理・グループ同期

| 項目 | 内容 |
| :--- | :--- |
| アカウント認証 | Firebase Authentication（メール/パスワード） |
| 家計の共有 | 2つのアカウントを1つの「ペア（グループ）」に紐付け、Firestore の同じ領域を参照・更新 |
| グループ参加 | **招待コード方式**（6〜8桁英数字）。作成者がコードを発行し、2人目が入力して参加 |
| メンバー割当 | グループ作成者が `kai` / `miyuu` のどちらかを選択。2人目は残りのスロットに自動割当 |
| 表示名 | UI 固定ラベル「かい」「みゆう」（`paidBy` キーと対応） |

### 2.2 爆速入力機能

スマホから片手で、数秒で登録を完了するための専用 UI を提供します。

| 機能 | 説明 |
| :--- | :--- |
| 簡易電卓付きテンキー | `10000 - 2439` のような数式を入力すると、その場で計算して結果をセット（Excel の「割引」メモに相当） |
| 支払い者の即時選択 | 「かい」「みゆう」のトグル。ログインユーザーがデフォルト選択 |
| カテゴリのワンタップ選択 | 下記5カテゴリの特大アイコンボタン |
| 品名・備考入力 | テキスト自由入力（空欄でも保存可） |
| 未入力（仮登録）トグル | 金額未確定・請求未到着のデータを仮ステータスで保存。精算・合計から自動除外 |

**カテゴリ一覧**

| 表示 | キー |
| :--- | :--- |
| 🏠 生活用品 | `lifestyle` |
| 🍚 食費 | `food` |
| 🛋️ 家具・家電 | `furniture` |
| 💡 光熱費 | `utility` |
| 🧺 その他 | `other` |

### 2.3 ダッシュボード & 自動精算表示

アプリ起動時に最初に表示する、現在の家計状態のサマリー画面です。

| 要素 | 説明 |
| :--- | :--- |
| 今月の総合計金額 | 確定済み支出の合算（例: 376,604円） |
| 投資比率・実績 | かい / みゆうの支払合計をバーグラフで表示 |
| 自動精算ナビ | 2人の支払差額から、50:50 折半に必要な送金を1行で表示 |
| 未確定アラート | 未入力ステータスの件数を画面上部に警告表示 |

**精算ナビの表示例**

> みゆう から かい へ **50,961円** の支払いが必要です

計算ロジックの詳細は [logic.md](./logic.md) を参照。

### 2.4 明細一覧（履歴）

過去および当月のすべてのデータをタイムライン形式で表示します。

| 機能 | 説明 |
| :--- | :--- |
| 月別フィルタ | タブ切り替え（「5月分」「6月分」など） |
| 表示フィルタ | 「すべて」「かいの支出」「みゆうの支出」「未確定のみ」 |
| 明細カード | 左にカテゴリ絵文字、品名・金額・支払者を1行でコンパクト表示 |
| 未確定のハイライト | 未入力アイテムは背景を薄い黄色などで強調 |

## 3. 技術スタック

| 区分 | 選定技術 | 採用理由 |
| :--- | :--- | :--- |
| フロントエンド | Next.js (React) + TypeScript | Windows で容易に構築。ページ遷移が高速。スマホアプリ並みの UI/UX |
| デザイン・UI | Tailwind CSS + shadcn/ui | レスポンシブなコンポーネントを素早く実装 |
| バックエンド・DB | Firebase (Cloud Firestore) | サーバーレス・低コスト。リアルタイム同期が容易 |
| 認証 | Firebase Authentication | 2人の安全なログインを最小限の手間で実装 |
| ホスティング | Vercel / Firebase Hosting | コマンド一発でデプロイ可能（無料枠で対応） |

## 4. データベース設計（Cloud Firestore）

グループ ID 配下に支出ドキュメントがぶら下がる構造です。

### 4.1 `groups` コレクション

```
groups/{groupId}
  ├── members: {
  │     kai: string | null,    // Firebase UID（かい のスロット）
  │     miyuu: string | null   // Firebase UID（みゆう のスロット）
  │   }
  ├── inviteCode: string       // 6〜8桁英数字（2人目の参加用）
  └── createdAt: Timestamp
```

**グループ参加フロー**

1. 作成者がログイン後、自分のロール（`kai` または `miyuu`）を選択してグループを作成
2. システムが `inviteCode` を発行し、作成者の UID を選択ロールのスロットに設定
3. 2人目がログイン後、招待コードを入力して参加し、空いているスロットに UID が設定される

### 4.2 `expenses` サブコレクション

パス: `groups/{groupId}/expenses/{expenseId}`

```typescript
interface Expense {
  id: string;          // ドキュメント ID（自動生成）
  date: string;        // 発生日 (YYYY-MM-DD)
  category: 'lifestyle' | 'food' | 'furniture' | 'utility' | 'other';
  title: string;       // 品名・内容（例: "レック 激落ちくん"）
  amount: number;      // 金額（例: 1236）
  paidBy: 'kai' | 'miyuu'; // 支払ったユーザー
  isPending: boolean;  // true の場合、精算・合計から除外
  note?: string;       // 備考（例: "割引 -2,439円"）
  createdAt: Timestamp; // サーバータイムスタンプ
}
```
